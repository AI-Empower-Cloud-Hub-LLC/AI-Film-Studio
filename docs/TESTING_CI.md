# CI/CD Testing Pipeline

Guide for understanding and maintaining the GitHub Actions CI/CD pipeline for AI Film Studio.

## Pipeline Overview

The project has three workflow files in `.github/workflows/`:

| Workflow | File | Trigger | Purpose |
|---|---|---|---|
| CI/CD Pipeline | `ci.yml` | Push/PR to `main`, `develop` | Backend tests, frontend lint/build, Docker build |
| Deploy Frontend | `deploy-frontend.yml` | Push to `main` | Build and deploy Next.js to GitHub Pages |
| CI (basic) | `blank.yml` | Push/PR to `main` | Placeholder (echo only) |

## CI/CD Pipeline (`ci.yml`)

This is the primary quality gate. It runs three parallel jobs on every push and pull request.

### Job 1: Backend Tests

**Runner**: `ubuntu-latest`

**Services**:
- PostgreSQL 15 (port 5432) with health checks
- Redis 7 (port 6379) with health checks

**Steps**:

1. Checkout code
2. Set up Python 3.11
3. Cache pip dependencies (`~/.cache/pip`)
4. Install `backend/requirements.txt`
5. Run `pytest tests/ -v --cov=app --cov-report=xml`
6. Upload `coverage.xml` to Codecov

**Environment variables** provided to the test step:

| Variable | Value |
|---|---|
| `DATABASE_URL` | `postgresql://postgres:postgres@localhost:5432/ai_film_studio_test` |
| `REDIS_URL` | `redis://localhost:6379/0` |
| `SECRET_KEY` | `test-secret-key` |
| `OPENAI_API_KEY` | `test-key` (placeholder; tests don't call real APIs) |

Note: Tests use an in-memory SQLite database via `conftest.py` fixtures. The PostgreSQL service is available for integration tests that need a real database, but current tests do not use it.

### Job 2: Frontend Tests

**Runner**: `ubuntu-latest`

**Steps**:

1. Checkout code
2. Set up Node.js 20 with npm cache
3. `npm ci` in `frontend/`
4. `npm run lint` &mdash; ESLint static analysis
5. `npm run build` &mdash; TypeScript type checking and production build

### Job 3: Docker Build

**Runner**: `ubuntu-latest`

**Steps**:

1. Checkout code
2. Set up Docker Buildx
3. Build backend Docker image (`ai-film-studio-backend:latest`)
4. Build frontend Docker image (`ai-film-studio-frontend:latest`)

Both builds use GitHub Actions cache (`type=gha`) for layer caching. Images are not pushed to a registry (`push: false`).

## Deploy Frontend (`deploy-frontend.yml`)

Runs only on pushes to `main` (not on PRs).

**Steps**:

1. Checkout code
2. Set up Node.js 22
3. `npm ci` in `frontend/`
4. `npm run build` with `GITHUB_PAGES=true` environment variable
5. Upload `frontend/out/` as a Pages artifact
6. Deploy to GitHub Pages

**Permissions**: `contents: read`, `pages: write`, `id-token: write`.

**Concurrency**: Only one deployment at a time (`group: "pages"`, `cancel-in-progress: false`).

## Adding New CI Steps

### Adding a Backend Test Step

To add a new test stage (e.g. agent-specific tests):

```yaml
- name: Run agent tests
  env:
    DATABASE_URL: postgresql://postgres:postgres@localhost:5432/ai_film_studio_test
    REDIS_URL: redis://localhost:6379/0
    SECRET_KEY: test-secret-key
  run: |
    cd backend
    pytest tests/ -m "not slow" -v
```

### Adding Frontend Tests

When a JavaScript test runner is added (Vitest or Jest), add a step after the lint step:

```yaml
- name: Run unit tests
  run: |
    cd frontend
    npm test
```

### Adding E2E Tests

For Playwright-based E2E tests that require both frontend and backend:

```yaml
e2e-tests:
  name: E2E Tests
  runs-on: ubuntu-latest
  needs: [backend-tests, frontend-tests]
  steps:
    - uses: actions/checkout@v3
    - name: Start services
      run: docker-compose up -d
    - name: Wait for services
      run: |
        until curl -s http://localhost:8000/health | grep healthy; do sleep 2; done
    - name: Install Playwright
      run: |
        cd frontend
        npm ci
        npx playwright install --with-deps
    - name: Run E2E tests
      run: |
        cd frontend
        npx playwright test
    - name: Stop services
      if: always()
      run: docker-compose down -v
```

## Caching

| What | Cache key | Restore key |
|---|---|---|
| pip packages | `${{ runner.os }}-pip-${{ hashFiles('backend/requirements.txt') }}` | `${{ runner.os }}-pip-` |
| npm packages | Built-in via `setup-node` `cache: 'npm'` | N/A |
| Docker layers | `type=gha` (GitHub Actions cache) | `type=gha` |

## Coverage

Coverage is uploaded to [Codecov](https://codecov.io) from the backend test job via `codecov/codecov-action@v3`. The `coverage.xml` file is generated by `pytest-cov`.

To view coverage reports locally:

```bash
cd backend
pytest --cov=app --cov-report=html
open htmlcov/index.html
```

## Troubleshooting

### Backend Tests Failing in CI

1. Check that new Python dependencies are added to `backend/requirements.txt`.
2. Ensure tests do not depend on external API keys (mock all LLM calls).
3. Verify that `conftest.py` fixtures create all required database tables.

### Frontend Build Failing in CI

1. Run `npm run lint` and `npm run build` locally first.
2. Check for TypeScript type errors (`npx tsc --noEmit`).
3. Ensure new dependencies are committed in `frontend/package-lock.json`.

### Docker Build Failing

1. Check that `backend/Dockerfile` and `frontend/Dockerfile` exist and are valid.
2. Ensure all `COPY` paths reference files that exist in the repo.
3. Test locally with `docker-compose build`.
